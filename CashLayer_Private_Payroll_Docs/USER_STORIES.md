# User Stories and Acceptance Criteria

## Employer
- As an employer, I want to create a payroll batch so I can prepare multiple payments.
- As an employer, I want to review recipients and totals before signing.
- As an employer, I want clear transaction status so I know which payments executed.
- As an employer, I want duplicate execution protection.

## Employee
- As an employee, I want to verify my confidential payment.
- As an employee, I want to view my encrypted balance through the supported SDK.
- As an employee, I do not want other users to see my salary amount.

## Auditor
- As an authorized auditor, I want to verify payroll compliance within my granted scope.
- As an auditor, I need clear evidence of what the system did and did not verify.

## Public observer
- As a public observer, I want to verify on-chain execution.
- I must not be able to reveal confidential salary amounts or balances.

## Acceptance criteria
Every story must have positive, negative, authorization, privacy, and transaction-state tests before release.
